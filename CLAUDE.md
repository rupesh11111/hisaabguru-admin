# hisaabGuru admin

Next.js 16 web admin panel — global product catalog, shops, users, roles, subscription
plans. Runs on **3100**. Talks to the NestJS API directly from the browser; no server of
its own beyond Next rendering.

`README.md` here is accurate and current — read it for setup, bulk import and deploy.
This file covers only what it does not.

This is **the** admin surface. The Expo app's `app/admin/*` screens are deleted and the
backend's Vite console at `/console` is sign-in only ("Coming soon"). Build admin
features here.

## Gotchas



- `NEXT_PUBLIC_API_BASE_URL` must be a Docker **build arg**. Next inlines `NEXT_PUBLIC_*`
  during `next build`, so setting it only at `docker run` ships an image still pointing
  at the `http://localhost:8000/api/v1` fallback in `lib/api.ts` — the container starts
  fine and every call fails in the browser.
- The API's `CORS_ORIGINS` must list this app's origin. Missing it surfaces here as
  `Network error: Failed to fetch`, which looks like the API is down.
- The route guard in `src/app/(admin)/layout.tsx` is a convenience redirect only. Every
  request is authorized server-side on the `admin:access` permission; forcing a URL just
  yields 403s.
- `AGENTS.md` is generated by `next dev` — commit changes to it with your work rather
  than reverting them, or they just come back.

## Catalog work

There is no camera scanner: a desk admin uses a USB scanner in keyboard-wedge mode, so
barcode inputs just accept Enter. Every barcode is check-digit validated and normalised
to GTIN-13 before it leaves the browser, which is what stops a UPC-A and its EAN-13 form
creating two rows for the same trade item — the backend normalises identically.

`lib/openfoodfacts.ts` looks codes up across Open Food/Beauty/Products Facts with
retry, a TTL cache and single-flight dedup. Coverage for Indian SKUs is patchy — it
prefills a form, it is not a source of truth. Its `quantity` ("100 g") is a pack size:
it goes in `packSize`, never in `unit`.

Category and unit are picked from `catalogOptionsApi`, but older rows hold free text the
list does not contain. The product form must keep showing such a value as an old value,
or the select displays the first option while the form still holds the text.

Bulk import must never send a row with a blank name: `items` is validated as a whole, so
one such row is a 400 for the batch and the per-row reporting never runs.

Approving a product here is what lets it be prefilled into **other** shops' inventories
(backend `verification: provisional → verified`). Editing name/category/unit propagates
into every shop that has not customised that field and notifies them by push. Both are
cross-tenant and audited — see `hisaabguru-backend/CLAUDE.md` before changing anything
on the API side of this.
